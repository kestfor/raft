# REST API

Локальные конфиги и Docker Compose публикуют HTTP на портах `18001–18003`.
Один узел с `configs/raftnode.yaml` использует `18001`; без конфига — `8080`.
Адрес задаётся через `http_listen`, `RAFT_HTTP_LISTEN` или `--http-listen`.

## Status

```sh
curl -sS http://127.0.0.1:18001/v1/status | jq
curl -sS http://127.0.0.1:18002/v1/status | jq
curl -sS http://127.0.0.1:18003/v1/status | jq
```

В ответе: `id`, `role`, `term`, `leader_id`, `last_log_index`, `commit_index`.

## Show log

```sh
curl -sS http://127.0.0.1:18001/v1/log | jq
curl -sS 'http://127.0.0.1:18002/v1/log?from=1&limit=10' | jq
curl -sS 'http://127.0.0.1:18003/v1/log?from=11&limit=10' | jq
```

Ответ содержит `entries`, `last_log_index`, `commit_index`. У записи есть `index`,
`term`, `data` в base64 и `no_op`. Посмотреть текстовые команды:

```sh
curl -sS http://127.0.0.1:18001/v1/log \
  | jq '.entries[] | {index, term, no_op, data: (.data | @base64d)}'
```

`from` — начальный индекс включительно, по умолчанию `1`; `limit` — число записей,
по умолчанию `100`, максимум `1000`. Страница вмещает 4 MiB данных или одну более крупную команду;
для следующей страницы используй индекс последней полученной записи + 1.
Запрос за концом журнала возвращает пустой массив.

Это локальный диагностический снимок: записи с `index > commit_index` ещё
не подтверждены и могут быть заменены. Разные страницы могут видеть разные версии
неподтверждённого хвоста. В журнал входят служебные no-op записи.

## Propose

Сначала найди лидера по `role` в status и подставь его порт:

```sh
curl -sS -i --data-binary 'hello raft' http://127.0.0.1:18001/v1/propose
curl -sS -i -H 'Content-Type: application/octet-stream' \
  --data-binary @command.bin http://127.0.0.1:18001/v1/propose
```

Тело — сырые байты, до 2 147 418 111 байт на 64-битном узле; пустая команда допустима. Успех — HTTP 200
и `{"index": N}` после commit большинством, до выполнения state machine.

Ошибки возвращаются как JSON с полем `error`:

- `409` — узел не лидер или потерял лидерство; `leader_id` указывает известного лидера.
- `413` — размер тела превышает лимит команды.
- `504` — commit не подтверждён за 5 секунд.
- `503` — узел остановлен или контекст запроса отменён.
- `400` — неверные параметры или ошибка чтения тела; `500` — внутренняя ошибка.

Если запись уже добавлена, ошибка содержит её `index`. Она ещё может попасть
в commit; повтор запроса создаёт новую запись. Автоматического redirect нет.
